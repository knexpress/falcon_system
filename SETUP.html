Falcon Revive — Device Setup

Single-laptop install · Frontend + Backend + Database together

Use this page on the client laptop. Everything runs locally on the same machine: the React website, the Express API, and the SQLite database file. No cloud hosting required.

Windows laptop Frontend :5173 Backend API :4000 SQLite file database

1. What runs on this laptop

Frontend React website http://localhost:5173
Backend Express API http://localhost:4000
Database SQLite file backend/data/garage.db

Browser → Frontend (5173) → API proxy → Backend (4000) → SQLite database on disk. All three live on the same laptop.

2. Install once (prerequisites)

  1. Install Node.js LTS (18+) from nodejs.org — tick “Add to PATH”.
  2. Install Python 3 from python.org — tick “Add python.exe to PATH” (needed for invoice PDF).
  3. Restart the laptop after installing.
  4. Copy the full falcon project folder onto the laptop (Desktop is fine).

Check installs in Command Prompt / PowerShell

node -v npm -v python --version

You should see version numbers for all three. If any command fails, reinstall and restart.

3. First-time project setup

Open PowerShell or Command Prompt and run these blocks one time.

A) Backend + database

cd Desktop\KNEXPRESS\falcon\backend npm install npm run seed python -m pip install pypdf

✓ This creates the SQLite database at backend\data\garage.db and loads demo data.

B) Frontend

cd Desktop\KNEXPRESS\falcon\frontend npm install

If your folder path is different, change Desktop\KNEXPRESS\falcon to the real location of the project on that laptop.

4. Start the system every day

You need two terminals open (or double-click the starter files below).

Terminal 1 — Backend + Database

cd Desktop\KNEXPRESS\falcon\backend npm start

Wait until you see: Garage Finance API running on http://localhost:4000

Terminal 2 — Frontend website

cd Desktop\KNEXPRESS\falcon\frontend npm run dev

Wait until Vite shows: http://localhost:5173

Or use the included starter files

  1. Double-click start-backend.bat in the falcon folder
  2. Double-click start-frontend.bat
  3. Or double-click start-all.bat to open both

6. Where things live on disk

Part Path on laptop
Project root falcon\
Backend API falcon\backend\
Database file falcon\backend\data\garage.db
Frontend app falcon\frontend\
Invoice PDF template falcon\backend\invoice-pdf\
Price list falcon\backend\pricing.txt

Your past work stays on this laptop. Invoices, customers, vehicles, sales, expenses and inventory are saved inside garage.db. Closing Chrome or stopping the app does not erase them. Next time you run start-all.bat, everything opens again from the same file.

Backup tip: double-click backup-database.bat (or copy garage.db to USB/OneDrive). That one file is the full business history. Never delete the backend\data folder.

7. Stop / restart

  • In each terminal window press Ctrl + C to stop.
  • To restart later, run the same start commands (or the .bat files) again.
  • You do not need to run npm install or seed every day.

8. Troubleshooting

Problem Fix
node / npm not recognized Reinstall Node.js LTS and restart laptop
Port 4000 or 5173 already in use Close old terminal windows, or restart the laptop
Frontend loads but data fails Make sure Terminal 1 (backend) is still running
PDF download fails Run python -m pip install pypdf again
better-sqlite3 install error Install “Desktop development with C++” Build Tools, then npm install in backend again
Empty / wrong data after copy Confirm you copied the whole falcon folder including backend\data

9. Quick checklist for the client

  1. ☐ Node.js installed (`node -v`)
  2. ☐ Python installed (`python --version`)
  3. ☐ `npm install` done in backend and frontend
  4. ☐ `npm run seed` done once in backend
  5. ☐ `pypdf` installed
  6. ☐ Backend started on port 4000
  7. ☐ Frontend started on port 5173
  8. ☐ Chrome opens http://localhost:5173
  9. ☐ Staff can log in and open invoices
  10. ☐ Database backup location known (`backend\data\garage.db`)
  11. ☐ Confirmed past invoices still show after closing and reopening the app
  12. ☐ Ran `backup-database.bat` at least once
